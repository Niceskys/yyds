## 5. 最小升级方案（已执行）

原则：patch > minor > 精确 transitive > major（仅在必要时）。

| Package | old | new | 类型 | 是否 breaking | 依据 |
| --- | --- | --- | --- | --- | --- |
| `vite` | 5.4.11 | 5.4.21 | patch（同 major） | 否 | 5.4.21 是最后一个 5.4.x 版本（2025-10-20 发布），一次移除 9 条 vite advisory |
| `vitest` | 2.1.8 | 2.1.9 | patch（同 major） | 否 | 2.1.9 修复 critical `GHSA-9crc-q9x8-hgqq` |

- 使用项目一致的**精确版本锁定**（不带 `^`）。
- `@vitejs/plugin-react@4.3.4` 的 peer range 为 `vite ^4.2.0 || ^5.0.0`，与 5.4.21 兼容，无需改动。
- `vitest@2.1.9` 的 peer range 为 `vite ^5.0.0`，与 5.4.21 兼容，无需改动。

### 5.1 lockfile 生成方式与变更范围

`web/package-lock.json` 由一次性 bootstrap workflow 在 GitHub runner（Node 20）上以 `npm install --package-lock-only` 重新生成并提交（bot commit `dab8f7d`）。生成结果与本工作区本地生成的 lockfile **逐字节一致**：

```text

```

该临时 workflow 已在同一 PR 中删除，最终 PR diff 不含任何 CI 变更。采用该方式的原因是本次 AI 工作区无法通过 GitHub contents API 可靠推送约 111 KB 的 lockfile；此为工具链限制，不改变升级本身的最小性。

lockfile 只发生 11 处条目变化，全部属于 vite / vitest 依赖簇，无无关依赖升级：

### 6.2 为什么 npm 总数从 4 变成 5

- npm 的 `total` 统计的是**被标记的包节点数**，不是 advisory 数。
- 升级 `vite` 到 5.4.21 后，npm 额外把传递依赖 `vite-node@2.1.9` 单列为一条 moderate 节点，其 `via` 为 `["vite"]`，**没有独立 advisory**，只是 vite advisory 的聚合投影。
- 因此数字上升不代表风险上升。按 advisory 粒度：

```text
before: 16 条（vite 12 + esbuild 1 + vitest/@vitest-mocker 3）
after:   6 条（vite 3 + esbuild 1 + vitest/@vitest-mocker 2）
移除:   10 条（含 critical GHSA-9crc-q9x8-hgqq + 9 条 vite dev-server advisory）
```

### 6.3 npm `fixAvailable` 不可直接信任的证据

`npm audit --json` 对 `@vitest/mocker` 给出：

```json
"fixAvailable": { "name": "vitest", "version": "3.2.7", "isSemVerMajor": true }
```

但同一份 JSON 中该 advisory 的区间是 `>=2.1.0 <4.1.11`，而 `3.2.7` 落在该区间内。也就是说 npm 建议的 “fix” 并不能真正修掉这条 advisory。这正是 Issue #45 禁止直接 `npm audit fix --force` 的直接证据。

## 9. 后续触发条件

满足任一条件即应重新开 Issue 处理：

1. 需要启用 Vitest UI / `--api`，或把 `npm run dev` 的 dev server 暴露到 localhost 之外；
2. 需要引入 `vi.mock` 且 mock 路径可能来自不可信输入；
3. 前端进入需要长期维护的发布阶段，决定把工具链整体升到 `vite` ≥ 6.4.3 / `vitest` ≥ 4.1.11；
4. npm / GitHub Advisory 出现针对当前 vite 5.x / vitest 2.x 的**新的生产可达**漏洞；
5. B4 完成、真实 API 接入稳定后，启动独立的前端工具链 major 升级任务（需在 Node 20 CI 下验证）。
