# 《规则之外》可行性测试器

这是正式游戏开发前的无界面压力测试程序。默认运行的是第三轮“策略意图 → 确定性规划 → 模拟验证”测试，而不是棋盘 UI：

> 玩家颁布公共规则 → AI 找到反制策略 → 确定性引擎验证 → 玩家追加修正规则 → AI 再适应。

## 运行

要求 Python 3.11+，不依赖第三方包。

```powershell
$env:GLM_API_KEY = "你的密钥"
$env:GLM_BASE_URL = "https://open.bigmodel.cn/api/paas/v4"
$env:GLM_MODEL = "glm-5.1"
python -m rule_beyond --provider glm --suite final --output reports/final-validation.json
```

`GLM_BASE_URL` 可替换为赛事平台提供的 OpenAI 兼容地址。密钥只读取环境变量，绝不会写入报告或仓库。

真实测试默认每关最长等待 120 秒，传输超时后自动重试两次，并会实时显示关卡进度。接口超时会单独统计，不能当作模型答错；少于 5 个有效回答时，报告不会给出立项结论。

策略测试会关闭 GLM 的深度思考模式，并为最终 JSON 分配 1024 tokens；这能避免推理过程占满输出额度而没有留下可验证策略。

在未配置接口时，可用确定性的离线基准模式检查引擎与评测链路：

```powershell
python -m rule_beyond --provider fixture --output reports/fixture-report.json
```

## 最终验证判定

模型只能看到完整棋盘局面、公共规则、动作语义与“蓝方尽量获胜”的通用目标；它看不到正确意图、参考方案、通过收益阈值及对照答案。GLM 只输出最多两个高层策略意图；规划器系统化枚举该意图对应的合法行动方案，模拟器实际结算收益，并与不利用公共规则的基线策略比较。

测试含 8 个正向规则边界和 2 个“应避免有害触发”的对照局。通过门槛为：策略理解至少 8/10、规划执行至少 9/10、正向局真实收益至少 7/8、对照局正确处理 2/2。`fixture` 模式只用于程序自检，不能用于 GLM 的立项结论；正式结论必须使用 `--provider glm`。

## 约束

- 只支持有限 DSL；大模型只能返回候选策略，不能直接修改游戏状态。
- 测试采用 10 个盲测局面，不是正式游戏，也不包含前端。
- 正确意图、参考行动与通过阈值只存于本地案例数据，不会进入模型提示词。
